# F4. 냉장고 재료 관리

명세 출처: `기능명세서.md` 292~314행, 시나리오 S5(471~477행).
공통 상수·타입은 [`diet-domain`](../diet-domain/SKILL.md)을 따른다.

보유 중인 식재료 목록을 관리한다. **재료를 버리지 않게 하는 것**이 목적이고, 출력은 F6 레시피 추천의 입력이 된다.

## 데이터 모델

`FridgeItem` (→ `diet-domain/references/types.md`), 테이블 `fridge_items`.

## 입력

- 재료명, 수량/단위, 구매일(기본값 오늘), 유통기한(선택)
- 냉장고 사진 업로드 — **1차 배포 미구현**

> **사진 재료 인식은 1차 배포에 넣지 않는다** (미결정 #1). 명세도 "이 앱에서 기술적으로 가장 무거운 부분"이며 "초기 버전을 수동 입력만으로 출시해도 F1~F7 전부 동작한다"고 판단하고 있다(508행). UI에는 업로드 자리를 두되 **'준비 중'으로 비활성 표시**하고, 옆에 수동 추가 버튼을 둔다. 자리를 아예 없애지 않는 이유는 나중에 붙일 위치를 지금 정해두기 위함이다.

사진 인식을 나중에 붙일 때의 규약도 지금 정해둔다 — **인식 결과를 자동 저장하지 않는다.** 후보 목록을 사용자 확인 단계로 넘겨 승인/수정/추가를 거친 뒤에만 보유 목록에 반영한다 (명세 302~303행). 인식 정확도는 100%가 아니기 때문이다.

## 처리·출력

- 보유 재료 목록 (재료명, 수량, 유통기한)
- 유통기한이 입력된 재료는 임박 여부 판단 — **3일 이내면 강조 표시**
- 정렬은 임박 → 구매일 순

## 검증·엣지케이스

- **사진 인식은 보조 수단이다.** 없어도 수동 입력만으로 F4와 F6이 온전히 동작해야 한다
- **레시피를 만들었다고 재료를 자동 차감하지 않는다.** 실제 사용량을 앱이 알 수 없다. 소진은 사용자가 직접 삭제한다 (명세 314행)
- 유통기한이 이미 지난 재료는 삭제하지 않고 별도로 표시한다 — 버리는 판단은 사용자 몫
- 수량 0 이하 거부
- 유통기한 < 구매일 이면 입력 오류 안내
- 같은 이름의 재료를 또 등록하면 합칠지 따로 둘지 묻는다 (구매일·유통기한이 다를 수 있다)

## 완료 판정

S5 — 양파·계란·두부·대파·닭가슴살 5개를 수동 등록하고 두부에 유통기한을 3일 뒤로 입력 → 보유 목록 5개, **두부에 임박 표시**. 사진 업로드 자리는 '준비 중'으로 보이고 클릭해도 아무 일이 없다.
