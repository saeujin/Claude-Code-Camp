# F2. 하루 식단 기록

명세 출처: `기능명세서.md` 203~226행, 시나리오 S2(429~435행)·S6(489~491행).
공통 상수·반올림·타입은 [`diet-domain`](../diet-domain/SKILL.md)을 따른다.

## 데이터 모델

`MealEntry`, `Food` (→ `diet-domain/references/types.md`), 테이블 `meal_logs`·`custom_foods`.

## 입력

- 끼니 구분 — 아침 / 점심 / 저녁 / 간식
- 음식 이름 — `foods.json` 시드 + `custom_foods`에서 검색, 없으면 직접 입력
- 섭취량 — **인분 또는 g**. 인분으로 받아도 `Food.servingG`로 환산해 **g으로 저장**한다
- 날짜 — 기본값 오늘

## 처리

```
① 음식 DB에서 100g당 칼로리·탄단지 조회
② 섭취량(g)만큼 환산     nutrition = per100g × (amountG ÷ 100)
③ 환산 결과를 meal_logs에 저장 (조회가 아니라 값으로 굳힌다)
④ 그날 전체 기록을 합산해 누적 섭취 칼로리·탄단지 산출
```

**②의 환산 결과를 그대로 저장하는 이유** — 나중에 음식 DB 값이 수정되어도 과거 기록의 숫자가 바뀌면 안 된다. `food_id` 참조가 아니라 계산된 영양소를 기록에 박아둔다.

DB에 없는 음식은 사용자가 칼로리(와 선택적으로 탄단지)를 직접 입력하고, `custom_foods`에 저장해 다음부터 검색된다.

## 출력

- 끼니별 기록 목록
- 오늘 누적 섭취 칼로리 / 탄단지
- **잔여 칼로리** = 오늘 목표 − 누적 섭취 — 오늘 목표는 F3의 운동 소모가 반영된 값이다. 기본 목표가 아니다

## 검증·엣지케이스

- 기록 수정·삭제 시 누적값 **즉시 재계산**
- **목표를 초과해도 기록을 막지 않는다.** 잔여를 음수로 표시할 뿐이고, 초과 안내는 F7이 담당한다
- **F1 미완료 상태에서는 기록은 가능하되 잔여 칼로리를 표시하지 않는다.** 0으로 표시하지 말 것
- 섭취량 0 이하 거부
- 미래 날짜 기록 거부, 과거 날짜 허용
- 같은 이름의 사용자 음식 중복 등록 방지 (`unique (user_id, name)`)

## 완료 판정

S2 — 아침에 계란 2개 + 토스트 2장 = **420 kcal** 기록 → 대시보드에 `420 / 1,581 kcal`, 잔여 **1,161 kcal**, 단백질 목표 119g 중 18g.

S6 — 저녁 510 kcal까지 기록해 하루 합계 **1,450 kcal** (아침 420 + 점심 520 + 저녁 510).

`foods.json` 시드에 계란·식빵·닭가슴살 샐러드·두부 계란찜·현미밥이 있어야 위 수치를 재현할 수 있다.
