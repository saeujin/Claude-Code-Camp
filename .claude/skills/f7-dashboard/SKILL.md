# F7. 일일 대시보드

명세 출처: `기능명세서.md` 381~400행, 시나리오 S2·S3·S6.
공통 상수·반올림·타입은 [`diet-domain`](../diet-domain/SKILL.md)을 따른다.

오늘 하루의 식단과 운동 현황을 한 화면에서 보여주는 **홈 화면**. F1의 목표값, F2의 식사 기록, F3의 운동 기록을 읽기만 하고 직접 쓰지 않는다.

## 표시 항목

1. **목표 진행 상황** — `현재 75.0kg → 목표 70.0kg`, 남은 기간(`11주 6일` 형태), 달성률
2. **목표 구성 분해** — `기본 목표 1,581 + 운동 311 = 오늘 목표 1,892`
   사용자가 **목표가 왜 늘었는지** 알 수 있어야 한다. 결과 숫자만 보여주지 않는다
3. 오늘 목표 대비 섭취 진행률 (`420 / 1,581 kcal` + 진행률 바)
4. 탄단지 각각의 목표 대비 섭취 비율 — 근력운동한 날은 **상향된 단백질 목표** 기준
5. 잔여 칼로리 (음수면 초과량으로 표시)
6. 끼니별 섭취 요약, 오늘 운동 요약
7. F5 추천 바로가기

`DaySummary` 하나를 만들어 화면 전체가 그것만 읽게 한다 (→ `diet-domain/references/types.md`).

## 확정 UI 문구

**섭취 부족 안내** (S6) —
*"목표보다 442 kcal 적게 드셨어요. 오늘 조깅으로 311 kcal를 쓰셨는데 그만큼 보충하지 않으셨네요. 섭취량 1,450 kcal는 기초대사량(1,699 kcal)보다도 적어서 오히려 감량에 방해가 돼요."*

세 부분으로 조립한다 — ① 부족량 ② 운동을 한 날이면 그 맥락 ③ 섭취가 BMR 미만이면 그 사실.

## 검증·엣지케이스

- 기록이 하나도 없으면 **빈 상태 화면**과 함께 기록을 유도한다
- **목표 초과 시 경고가 아닌 중립적 표현**을 쓴다. 사용자가 기록을 회피하게 만들지 않기 위함이다 (명세 398행). 붉은색·경고 아이콘·느낌표를 쓰지 않는다
- **섭취 부족도 관리 대상이다.** 하루가 끝나갈 시점(예: 21시 이후)에 섭취량이 BMR 미만이면 안내를 띄운다. F1이 기본 목표를 BMR 아래로 내리지 않는 것과 같은 이유다. 과다 섭취만 문제가 아니다 (명세 399행)
- 운동을 많이 한 날은 잔여가 크게 남아 위 안내가 뜨기 쉽다. 이때는 **"운동한 만큼 보충하세요"** 라는 맥락을 함께 보여준다 (명세 400행)
- **F1 미완료면** 목표·진행률·잔여를 표시하지 않고 프로필 설정으로 유도한다. 0으로 표시하지 말 것
- 목표 기간이 지났으면 진행 상황 대신 새 목표 설정을 유도한다

## 완료 판정

- **S2** 아침 420 기록 후 → `420 / 1,581 kcal`, 잔여 **1,161**, 단백질 119g 중 18g
- **S3** 조깅 311 기록 후 → `기본 목표 1,581 + 운동 311 = 오늘 목표 1,892`, 잔여 **1,472**, "기초대사량보다 낮아요" 경고 **사라짐**(1,892 > 1,699)
- **S6** 하루 합계 1,450 → **초과가 아닌 부족** 안내, 442 kcal 부족 + 운동 보충 맥락 + BMR 미만 사실. 상단에 `75.0kg → 70.0kg, 남은 기간 11주 6일`
