# F1. 사용자 프로필 및 목표 설정

명세 출처: `기능명세서.md` 85~199행, 시나리오 S1(406~425행). 애매하면 원문을 먼저 읽는다.
공통 상수·반올림·타입은 [`diet-domain`](../diet-domain/SKILL.md)을 따른다.

**앱을 쓰기 위해 반드시 먼저 완료해야 하는 기능.** 여기서 나온 기본 목표 칼로리가 나머지 모든 기능의 기준선이다.

## 데이터 모델

`Profile`, `GoalPlan` (→ `diet-domain/references/types.md`), 테이블 `profiles` (→ `diet-domain/references/schema.md`).

`GoalPlan`은 저장하지 않는다. `Profile`에서 매번 `buildGoalPlan()`으로 파생한다.

## 입력 폼

| 항목 | 형식 | 비고 |
|---|---|---|
| 성별 | 남 / 여 | BMR 공식이 갈림 |
| 나이 | 정수 (세) | 10~100 |
| 키 | 실수 (cm) | 100~250 |
| 몸무게 | 실수 (kg) | 30~300. 변경 시 재계산 |
| 활동 수준 | 4단계 중 택 1 | **운동은 제외**하고 고른다 |
| 식단 목표 | 다이어트 / 유지 / 증량 | |
| 목표 체중 | 실수 (kg) | 유지 목표일 때는 **입력받지 않는다** |
| 목표 기간 | 주 수 **또는** 목표 날짜 | 하나를 입력하면 나머지를 환산해 **함께 보여준다** |

활동 수준 선택지 아래에 안내 문구를 반드시 붙인다 — *"운동은 따로 기록하니 여기서는 빼고 골라주세요"* (명세 189행).

## 처리

계산은 전부 `diet-domain/references/formulas.md`의 ①~⑤. 여기서 다시 적지 않는다. 요지만:

```
BMR → TDEE → 일일 조정량 → 기본 목표 → 탄단지
```

**단계적 반올림**(BMR·TDEE·조정량을 각각 반올림한 뒤 기본 목표 계산)을 지키지 않으면 명세의 1,581이 1,580으로 나온다.

## 출력 — 계산 근거를 단계별로 노출한다

사용자가 왜 이 숫자인지 이해할 수 있어야 한다. 값만 던지지 않는다.

- **BMR → TDEE → 기본 목표** 세 값을 순서대로 (S1처럼 순차 등장 연출)
- **일일 조정량** — *"5kg을 12주에 빼려면 하루 458 kcal를 덜 드셔야 해요. 주당 0.42kg 속도예요."*
- **주당 예상 변화 속도** (kg/주) — 자기가 정한 기간이 어떤 속도인지 체감할 수 있어야 한다
- **목표 달성 예정일**
- 목표 탄수화물 / 단백질 / 지방 그램 수
- BMR 미만이면 — *"이 목표는 기초대사량(1,699 kcal)보다 낮아요. 기간을 늘리거나 운동을 병행하는 걸 고려해보세요."*
- 특수 상황 안내 — 임신·수유·질환은 이 공식이 다루지 않는다는 문구를 폼 하단에 상시 노출

## 검증·엣지케이스

- 필수 항목 미입력 시 **계산 버튼 비활성화**
- 입력 범위(나이 10~100, 키 100~250, 몸무게 30~300)를 벗어나면 오류 안내
- **목표 체중 = 현재 체중** → 어느 목표를 골랐든 유지로 처리, 조정량 0
- **기간이 짧아 목표가 0 이하로 계산되어도 값을 올리지 않는다.** 계산값을 그대로 보여주되 입력을 다시 확인하도록 유도
- **BMR보다 낮아도 값을 바꾸지 않는다.** 사실만 알린다. 속도를 정하는 건 사용자의 몫 (명세 130~133행)
- **몸무게 갱신 시** `남은 체중 변화량 ÷ 남은 기간`으로 조정량 재계산. 목표 체중·기간 자체는 유지
- **목표 기간 경과 시** 달성 여부 확인 후 새 목표 유도. 정하기 전까지 마지막 기본 목표를 그대로 사용
- 목표·기간 변경 시 기본 목표를 즉시 재계산하고 **변경 사실을 알린다**
