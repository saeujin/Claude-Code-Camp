# F6. 재료 기반 레시피 추천

명세 출처: `기능명세서.md` 353~377행, 시나리오 S6(481~489행).
공통 상수·타입은 [`diet-domain`](../diet-domain/SKILL.md)을 따른다.

냉장고에 있는 재료로 만들 수 있는 요리를 찾아준다. **재료를 버리지 않게 하는 것**이 목적이다.

## 입력

- F4의 보유 재료 목록
- (선택) 사용하고 싶은 재료 지정
- (선택) F5의 잔여 칼로리 — 칼로리 조건까지 반영할지 여부를 **사용자가 켜고 끈다**

## 처리

```
① 필요 재료 = recipe.ingredients.filter(i => !i.pantry)
   조미료·기본 양념(소금·후추·식용유 등)은 항상 보유한 것으로 간주해 제외한다

② 매칭률 = round(보유한 필요 재료 수 ÷ 필요 재료 수 × 100)

③ 매칭률 높은 순 정렬
④ 유통기한 임박(3일 이내) 재료를 쓰는 레시피에 가산점
⑤ 잔여 칼로리 조건이 켜져 있으면 범위를 넘는 레시피는 후순위로
```

가산점은 정렬 순서만 바꾸고 매칭률 숫자는 바꾸지 않는다. 표시되는 매칭률과 순서가 어긋나 보일 수 있으므로, 가산점을 받은 레시피에는 그 이유를 함께 표시한다 (예: "유통기한 임박한 두부를 써요").

재료명 대조는 정규화 후 비교한다 — 공백 제거, 소문자화. 완전 일치만 인정하고 부분 일치는 쓰지 않는다(대파와 파, 닭가슴살과 닭이 잘못 매칭된다).

## 출력

- 레시피 목록 — 요리명, 매칭률, 예상 칼로리
- 각 레시피의 **보유 재료** / **부족한 재료** 구분 표시
- 조리법

## 검증·엣지케이스

- 매칭률 100% 레시피가 없으면 **부족 재료가 1~2개인 것까지 포함**해 보여준다 (부족분을 명확히 표시)
- 보유 재료가 없으면 F4로 유도
- 조미료는 매칭률 계산에서 제외 — 시드 데이터의 `pantry: true` 플래그로 판단
- 필요 재료가 전부 조미료인 레시피는 매칭률 100
- **레시피를 만들어도 재료를 자동 차감하지 않는다** (F4와 동일 규칙, 명세 314행)
